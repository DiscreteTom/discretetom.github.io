## 栈和堆

不同编程语言会有不同的内存管理方式，但是通常都会有栈和堆的概念

> 这里的堆栈与数据结构中的堆和栈不同

- 栈
  - 存放函数调用的参数、局部变量、返回地址等
  - 是一块**连续**的内存区域
  - 生命周期短，速度快，高效
    - 比如在 C++ 中不需要手动使用`delete`进行释放，而是在生命周期结束时自动释放，比如函数返回后函数内的局部变量会被自动释放
  - 不能存放动态大小的数据
  - 地址从高位向低位增长
    - 比如从 `0x7fffffff` 到 `0x7ffffff0`
  - 不同的操作系统对栈的大小有限制
    - 比如 Windows 默认为 1MB
    - 比如 Linux 默认为 8MB
    - 可以通过修改操作系统的配置文件来调整栈的大小
- 堆
  - 存放动态分配的数据
  - 大小不固定
  - 大小通常只受到物理内存的限制，并且通常是不连续的
  - 生命周期长，速度慢
    - 比如在 C++ 中需要手动分配（使用`new/malloc`）和释放（使用`delete/free`）
    - 操作系统需要找到一块未使用且足够大的内存空间，然后将这块内存空间的地址返回给程序，所以慢
  - 操作不慎会导致内存泄露、内存溢出或访问非法内存
  - 地址从低位向高位增长
    - 比如从 `0x1000` 到 `0x2000`

> 在 rust 中如果函数的返回值引用了一个局部变量，它的生命周期就是不合法的，因为局部变量会在函数结束时被释放。而 rust 可以在编译期检查出来这个错误，赞美 rust！

【把栈上面的对象放到堆上面】称为【装箱/boxing】，反之则叫做【拆箱/unboxing】。装箱后，需要使用栈上的指针来访问堆上的对象，这样会增加一次寻址的开销

> 很多面向对象的编程语言里面的对象都是在堆上面创建的（说你呢 Java，一切皆对象啊？），而 rust 里面的 struct 实例默认是在栈上面创建的，效率会更高

通常来说在编译期无法确定大小的数据类型需要使用堆上内存，比如`String`和`Vec`

## 虚拟地址和物理地址

操作系统会将物理内存地址空间映射成虚拟内存地址空间，程序在启动时看到的虚拟内存是一块完整连续的内存（比如 32 位 Windows 是 4GB，详情可以参考[此文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/gettingstarted/virtual-address-spaces)）

程序启动的时候，操作系统会为每个线程分配一块固定大小的栈内存空间（大小由操作系统或编译器决定，通常 1MB 或 2MB，通常可以通过参数配置），这个栈空间由线程独享，不允许跨线程访问

堆内存则由程序主动申请，大小由程序在运行时决定

虚拟地址只有在被分配时才会和物理地址关联起来，这个过程叫做【页表映射】，粒度是【页】，通常是 4KB
